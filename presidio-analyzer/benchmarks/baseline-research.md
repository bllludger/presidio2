Дата: 24.11.2026. Задача №1 выполнена в границах локального baseline: зафиксированы два варианта, четыре независимых последовательных прогона дали точное повторение результатов. Код production и правила на этом шаге не менялись. [Результаты](baseline-summary.json), [manifest](baseline-manifest.json), [инструмент](freeze_baseline.py).

Первая часть — исходный аудит до запуска измерений; выполненные проверки и ограничения приведены в разделе «Выполненный baseline» ниже. Чеклист аудита включает также требования к будущему переносимому и нагрузочному стенду, которые не следует считать выполненными этим локальным прогоном.

### Холодное и прогретое состояние

«Без кеша» в имеющихся отчётах означает обход сервисного кеша итоговых диапазонов: вызывается непосредственно Detector, а не `CachedTextDetector.scan`. Сервис имеет локальный LRU на 1024 записи и необязательный shared/Redis слой. [Сервисный кеш](../../../litellm-presidio-port/src/presidio_ru_litellm/analyzer.py).

Однако внутри Detector остаётся `CachedPhoneRecognizer.replay`: он хранит межвызовные результаты строк, до 4096 записей, с ограничениями по суммарным символам и matches; применяется к текстам длиной 1024–65536 символов при выполнении дополнительных условий. Повтор текста и повтор строк между разными текстами способны использовать этот кеш. У worker в evaluation свой экземпляр, а распределение задач по worker влияет на его прогрев. Поэтому три прохода не являются тремя независимыми холодными наблюдениями. [PhoneReplay](../../../litellm-presidio-port/profile/src/phone_replay.py), [создание Detector](../../../litellm-presidio-port/profile/src/detector.py).

`lru_cache` функции lemma, напротив, создаётся **внутри каждого** `process_text`; он устраняет повторные разборы слов только в текущем тексте. Называть его кешем лемм между запросами по этому коду нельзя. [Контекстный движок](../../../litellm-presidio-port/profile/src/context_nlp.py).

Для нового baseline предлагается сохранить естественные внутренние оптимизации, но раздельно назвать режимы: cold process (новый процесс, импорт/конструктор/первый вызов отдельно), fresh workload (новые блоки после заданного warmup), repeated workload (явные повторы, внутренние кеши прогреваются), service cache hit (отдельный HTTP-тест). Это методическое предложение, не уже выполненные измерения.

## Полнота provenance и граница engine/rules

`evaluate_ru_port.tree_hash` включает только `.py/.yaml/.yml/.toml/.json/.txt`. Это ловит многие незакоммиченные изменения, но не wheel, native libraries и прочие расширения. В отчёт попадают версии только пяти зависимостей. Сам harness, его аргументы, полный installed inventory, реальные импортированные пути, переменные поведения, CPU-модель, RSS и сырые наблюдения не записываются. [Функции `tree_hash` и `main`](evaluate_ru_port.py).

В этой архитектуре «версия engine» не отделена от «версии rules» одним wheel: `presidio_analyzer/conf/gitleaks-source.toml` и встроенные RU recognizers поставляются вместе с библиотекой. Внешний профиль дополняет их YAML, field-labels, TOML расширением, Python recognizers и исключениями. `SourceAwareGitleaksRecognizer.load` объединяет встроенный TOML с `extension.toml`, компилирует его, затем преобразует allowlists; `Detector` подставляет field labels и проверяет фактический registry. Следовательно, один хеш исходного YAML или исходного TOML не описывает итоговую политику. [Встроенный Gitleaks](../presidio_analyzer/predefined_recognizers/generic/gitleaks_secret_recognizer.py), [адаптер](../../../litellm-presidio-port/profile/src/gitleaks_detector.py), [Detector](../../../litellm-presidio-port/profile/src/detector.py).

Ключ сервисного кеша уже хеширует Python version, lock, профильные `.py`, конфиги и все wheels. Он пригоден для разделения кешей, но не заменяет manifest измерения: в нём не сверяется содержимое фактически установленного пакета с лежащим рядом wheel. [Функция `profile_key`](../../../litellm-presidio-port/src/presidio_ru_litellm/span_cache.py).

Текущий `strict_scan` — контекст, превращающий обработанные regex timeout в `IncompleteScan`; сам по себе он не задаёт общий deadline всего Detector. Есть отдельное `REGEX_TIMEOUT_SECONDS`, читаемое при импорте. Baseline должен фиксировать текущее значение и контракт ошибок, не выдавая отсутствие общего deadline за изменение поведения в этом шаге. [Scan policy](../presidio_analyzer/scan_policy.py), [PatternRecognizer](../presidio_analyzer/pattern_recognizer.py).

## Предлагаемый checklist приёмки шага baseline

Это критерии для нового зафиксированного запуска, а не утверждение, что все пункты уже выполнены.

- [ ] Назван один baseline target: installed mask3 либо frozen source. Сохранены SHA-256 wheel и каждого runtime-файла, реальные import paths, Git HEAD + dirty status/patch + untracked runtime-файлы. Хеши проверяются до и после запуска; несовпадение делает запуск непригодным для сравнения.
- [ ] Frozen snapshot содержит engine вместе с встроенными правилами, полный профиль с configs/Python extensions, harness и зависимости для воспроизведения. Итоговый manifest ссылается на содержимое, а не только на живые абсолютные пути.
- [ ] Сохранены точный executable/Python/build/platform/architecture, полный список distribution с версиями, locks и хеши установленных файлов/native extensions либо проверенные артефакты их восстановления. Зафиксированы влияющие на анализ environment variables, CPU и доступные ресурсы. Не сохраняются секретные значения environment.
- [ ] Сохранены команда, UTC время, параметры workers/repeats/start method, fixed order/seed, warmup, определение cold/warm/cache; единицы метрик и границы каждого таймера. Не объявляется cold run после прогрева.
- [ ] Для каждого корпуса сохранены bytes SHA-256, количество cases/UTF-8 bytes/characters, порядок, уникальность ID, политика повторов и схемы labels. Synthetic cases фиксируются генератором и его хешем либо materialized corpus. Исходные чувствительные значения не попадают в публичный отчёт.
- [ ] Baseline quality измеряется без изменения правил: full/exact/partial/missed labels и touched negative labels/cases отдельно. Для неполной разметки не заявляется precision всего корпуса. Все predicted spans проходят bounds/order validation. [Текущие определения и unit-проверки](../tests/test_ru_benchmark_metrics.py).
- [ ] Повтор baseline против самого себя даёт идентичные диапазоны во всех режимах и workers. Контракт errors/incomplete scan фиксируется отдельно. Ожидаемые изменения диапазонов для будущего кандидата задаются явным reviewed artifact, а не автоматически принимаются.
- [ ] Сохраняются сырые либо по-case/per-repeat наблюдения без исходного текста и отдельные независимые процессы/повторы, чтобы оценить разброс. Агрегированные p95 трёх проходов не выдаются за доверительный интервал и воспроизводимость между запусками.
- [ ] Для сравнения движка fingerprint правил/профиля неизменен; для сравнения правил fingerprint движка неизменен. Если изменение затрагивает оба слоя, это прямо указано и не приписывается только ускорению engine.
- [ ] HTTP/LiteLLM, cache-hit, cold-start и open-loop capacity имеют отдельные отчёты и критерии; конечный локальный batch не используется как доказательство production RPS, deadline или fail-closed всей цепочки.

Минимальная граница завершения этого шага: восстановимый snapshot + проверяемый manifest + сохранённая команда и данные результатов + повторяемое равенство масок. Новые deadlines, правила и обещания производительности не требуются для принятия baseline.


## Выполненный baseline

Зафиксированы 480 файлов: исходники ядра, установленный пакет, профиль порта с правилами и wheels, код порта, шаблон конфигурации, lock-файлы, четыре корпуса и исполняемый harness. Manifest содержит версии и отпечатки файлов 75 установленных distributions, включая native extensions и данные словарей, отпечаток интерпретатора, Python/build/platform, значения ограниченного списка переменных поведения. Snapshot расположен в `presidio-ru-core/.baselines/2026-11-24-task1-v2/`, каталог создан с правами `0700` и собственным `.gitignore`. Полные тексты корпусов остаются в локальном snapshot; отчёты содержат координаты, счётчики и хеши.

SHA-256 manifest: `62dcc8b25971bf8279bebc7d5d57b554271b680229cc1f965ff6034086dce6bf`. Хеш закреплён в [summary](baseline-summary.json). Сами зависимости не скопированы в переносимый контейнер: запуск требует сохранённого окружения на этой машине. Git HEAD записан для ориентира; фактическую версию определяют сохранённые байты, включая незакоммиченные изменения. Полный Git diff посторонних файлов для запуска не требуется и не сохранялся.

Два отдельных варианта:

- `installed`: копия пакета из `.presidio-venv`, соответствующая wheel mask3. Это проверенный установленный пакет на диске; запущенные сервисы не перезапускались и их загруженные модули этим исследованием не проверялись.
- `core`: копия текущих исходников-кандидата. Отличается в трёх runtime-файлах, перечисленных в summary. Внешний профиль одинаков. В этой паре есть и прежнее изменение встроенного правила срока карты, поэтому сравнение не является чистым экспериментом только над движком.

### Корпуса и порядок работы

| Корпус | Случаи | Положительные метки | Отрицательные метки |
|---|---:|---:|---:|
| ПДн critical-250 | 250 | 662 | 64 |
| Секреты critical-250 | 250 | 496 | 658 |
| Hard negatives | 500 | 0 | 500 |
| Server 8/32 KB | 256 | нет разметки | нет разметки |

В каждом корпусе все тексты различны. Проверены уникальность ID, строковый тип входа, границы меток и совпадение размеченного значения с Unicode-срезом. Итог: 1 256 случаев, 6 016 338 UTF-8 байт. Точные размеры и хеши каждого корпуса находятся в summary. Серверный корпус используется для измерения стоимости, не для утверждений о качестве.

Каждый вариант выполнялся в двух отдельных последовательных процессах. Каждый процесс проходит все четыре корпуса дважды в фиксированном порядке, затем 12 раз каждый из трёх чат-сценариев. Нет искусственного RPS или параллельного CPU-тестирования. Первый проход означает первое использование в этом процессе; это не холодный OS cache. Второй проход сохраняет внутренние кеши профиля, в том числе PhoneReplay.

Чат-сценарии построены замороженным `messages_for`, входы каждого наблюдения имеют хеш:

- `new-chat`: пять новых блоков, прямой Detector, пять реальных вызовов.
- `history-chat`: четыре заранее прогретых полных блока и один новый короткий; один реальный вызов Detector.
- `mixed-chat`: поочерёдно пять новых блоков и четыре прогретых плюс один новый. Идентификаторы отделены от других сценариев, поэтому предшествующий тест не прогревает новый блок. Фактическое число вызовов проверяется assertion.

Полный span cache — только локальный `CachedTextDetector`; Redis и shared cache не задействованы. Внутренние кеши recognizers включены во всех режимах. «Новый блок» поэтому не означает отсутствие повторяющихся строк внутри него.

### Проверки и результаты

Пройдены 9 unit-тестов защиты baseline и 3 теста расчёта качества; Ruff check/format проходят. Проверяются добавление, удаление, изменение и переименование файлов во всех пяти деревьях, изменение зависимостей, wheel/native bytes, независимость поиска зависимостей от добавляемого source path, отказ от перезаписи snapshot, Unicode-разметка, несовместимость вариантов/manifest и несовпадение масок. [Тесты целостности](../tests/test_baseline_snapshot.py), [тесты метрик](../tests/test_ru_benchmark_metrics.py).

Все четыре полноценных прогона завершились: по 2 548 записей и 2 692 обращения к scan, суммарно 10 192 записи и 10 768 обращений. Часть обращений обслуживает кеш; это не число выполнений полного анализа. Хеши входов и окружения проверены до и после каждого прогона. Проверка не входит в CPU-таймер анализа. Выполняется именно копия harness из snapshot; результат нельзя записать поверх замороженных входов.

Для каждого варианта независимый повтор совпал по всем координатам, входным хешам и числу реальных вызовов Detector. Внутри каждого процесса первый и второй проходы также совпали по маскам. Между вариантами найдено только прежнее согласованное изменение: случай ПДн №111 получает диапазон `[16,23)` в обоих проходах. Оно совпадает с [ранее сохранённым ожидаемым изменением](reviewed-span-changes.json). Остальные диапазоны, включая отрицательные примеры, одинаковы.

| Качество на этом корпусе | installed | core |

### Повторение

Из корня `presidio-ru-core`, при сохранённом `.presidio-venv`:

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONHASHSEED=0 \
../litellm-presidio-port/.presidio-venv/bin/python \
.baselines/2026-11-24-task1-v2/harness/freeze_baseline.py run \
  --snapshot .baselines/2026-11-24-task1-v2 \
  --variant core \
  --output .baselines/2026-11-24-task1-v2/results/core-extra.json \
  --expect .baselines/2026-11-24-task1-v2/results/core-reference.json
```

Для установленного варианта заменить `core` на `installed` в трёх аргументах. При отличии входов, зависимости или ожидаемых масок команда завершается ошибкой и не публикует новый успешный результат. Версия с тем же номером, но другими байтами не считается той же базой. Команды четырёх выполненных прогонов сохранены внутри их JSON.

### Граница завершения

Завершена задача №1: локальный исходный уровень восстановим из snapshot при сохранённом окружении, проверяется на дрейф и воспроизводится. Код порта, движка, правил и работающих сервисов на этом шаге не менялся.

Не проверены перенос на Linux и другое железо, полная фиксация стандартной библиотеки/системных dynamic libraries, RSS под нагрузкой, несколько воркеров, Redis, HTTP/LiteLLM, общее время до модели, отмена и поведение при перегрузке. Контракт timeout не расширен и отдельная fault-injection серия в этот baseline не включена. Для 200/1000 чат-RPS нужны следующие задачи и отдельный нагрузочный стенд; эти четыре локальных прогона такой результат не обещают.
